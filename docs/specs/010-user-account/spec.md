# Feature Specification: การจัดการบัญชีผู้ใช้งาน

**Feature ID:** `010-user-account`
**Status:** Draft
**Source:** `docs/SRS.md`

## 1. Goal

ให้ผู้ใช้งานดู แก้ไข และจัดการข้อมูลบัญชีของตนเองได้ตามสิทธิ์ที่ระบบกำหนด

## 2. Scope

### In Scope

* ดูข้อมูลส่วนตัวของผู้ใช้งานเอง
* แก้ไขข้อมูลส่วนตัวที่ระบบอนุญาต
* จัดการข้อมูลบัญชีของผู้ใช้งานเองตามความสามารถที่มีอยู่ในระบบ
* ตรวจสอบสิทธิ์ก่อนดำเนินการกับข้อมูลบัญชี

### Out of Scope

* การสมัครสมาชิกและเข้าสู่ระบบ
* การสมัครเป็นนักเขียนและจัดการสิทธิ์นักเขียน
* การจัดการบัญชีผู้ใช้งานโดย Admin

## 3. Requirements

### R-USER-01 — ดูข้อมูลส่วนตัว

ระบบต้องให้ผู้ใช้งานดูข้อมูลส่วนตัวของตนเองได้

**Traceability:** `FR-USER-01`

### R-USER-02 — แก้ไขข้อมูลส่วนตัว

ระบบต้องให้ผู้ใช้งานแก้ไขข้อมูลส่วนตัวที่ระบบอนุญาตได้

**Traceability:** `FR-USER-02`

### R-USER-03 — จัดการข้อมูลบัญชีของตนเอง

ระบบต้องให้ผู้ใช้งานจัดการข้อมูลบัญชีของตนเองได้ตามความสามารถที่มีอยู่ในระบบ

**Traceability:** `FR-USER-03`

### R-USER-04 — ตรวจสอบสิทธิ์ก่อนดำเนินการ

ระบบต้องตรวจสอบสิทธิ์ก่อนดำเนินการกับข้อมูลบัญชีของผู้ใช้งาน

**Traceability:** `FR-USER-04`

## 4. Acceptance Criteria

* **AC-USER-01** เมื่อผู้ใช้งานเปิดดูข้อมูลส่วนตัว ระบบต้องแสดงข้อมูลของผู้ใช้งานนั้น
* **AC-USER-02** เมื่อผู้ใช้งานแก้ไขข้อมูลส่วนตัวที่ระบบอนุญาต ระบบต้องบันทึกข้อมูลที่แก้ไขของผู้ใช้งานนั้น
* **AC-USER-03** เมื่อผู้ใช้งานจัดการข้อมูลบัญชีของตนเอง ระบบต้องดำเนินการตามความสามารถที่มีอยู่ในระบบ
* **AC-USER-04** เมื่อมีการดำเนินการกับข้อมูลบัญชี ระบบต้องตรวจสอบสิทธิ์ของผู้ใช้งานก่อน

## 5. Constraints

* ผู้ใช้งานดำเนินการได้เฉพาะกับข้อมูลบัญชีของตนเอง
* การดำเนินการใดต้องเป็นไปตามบทบาทที่ระบบกำหนด
* การสมัครสมาชิกและเข้าสู่ระบบอยู่ในขอบเขตของ `009-authentication`
* การสมัครเป็นนักเขียนอยู่ในขอบเขตของ `012-writer-application`
* การจัดการบัญชีผู้ใช้งานโดย Admin อยู่ในขอบเขตของ `022-admin-user-management`
* ชื่อผู้ใช้ (`username`) ที่แก้ไขต้องมีความยาว 3-50 อักขระ (`VAL-03`)
* รูปโปรไฟล์ผู้ใช้ต้องไม่เกิน 5MB และเป็นไฟล์ภาพประเภท JPEG, PNG หรือ WebP เท่านั้น (`VAL-09`, `VAL-10`)
* การตรวจสอบข้อมูลขาเข้าเป็นไปตาม `FR-VALID-01` ซึ่งเป็นข้อกำหนดกลางตาม `docs/SRS.md` §3.1.17 — กฎ `VAL-01` ถึง `VAL-11` เป็นแหล่งอ้างอิงค่ากฎตามเดิม

## 7. Open Questions

* ข้อมูลส่วนตัวใดที่ระบบอนุญาตให้ผู้ใช้งานแก้ไขได้
  * **ข้อยุติจากการตรวจสอบระบบจริง:** อนุญาตให้แก้ไข `username` (`PUT /api/me/username`), `email` (`PUT /api/me/email`), `password` (`PUT /api/me/password`), รูปโปรไฟล์ (`PUT /api/me/profile-picture` หรือ `multipart/form-data`) และการตั้งค่าการแจ้งเตือน
* "จัดการข้อมูลบัญชีของตนเอง" ครอบคลุมการกระทำใดบ้างตามความสามารถที่มีอยู่ในระบบปัจจุบัน
  * **ข้อยุติจากการตรวจสอบระบบจริง:** ดูข้อมูลตนเอง (`GET /api/users`), แก้ไขโปรไฟล์, เปลี่ยนรหัสผ่าน, ระงับบัญชีชั่วคราว (`PUT /api/me/suspend`) และลบบัญชีผู้ใช้ (`DELETE /api/me`)
* เมื่อผู้ใช้งานจัดการบัญชีของตนเองแล้ว ข้อมูลที่เคยบันทึกไว้ เช่น ตำแหน่งการอ่าน ชั้นหนังสือ และการติดตามนักเขียน จะเป็นอย่างไร
  * **ข้อยุติจากการตรวจสอบระบบจริง:** หากเป็นการแก้ไขข้อมูลทั่วไป ข้อมูลทั้งหมดยังคงเดิม / หากลบบัญชี ระบบจะจัดการ Soft-delete หรือล้าง Session ตามนโยบาย Data Retention
* มีการยืนยันก่อนดำเนินการกับข้อมูลบัญชีหรือไม่ และต้องยืนยันด้วยข้อมูลใด
  * **ข้อยุติจากการตรวจสอบระบบจริง:** การเปลี่ยนรหัสผ่านต้องระบุ `current_password` เพื่อยืนยันตัวตน และทุกคำขอต้องแนบ Bearer JWT Token
