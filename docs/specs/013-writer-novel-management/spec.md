# Feature Specification: การจัดการนิยายของนักเขียน

**Feature ID:** `013-writer-novel-management`
**Status:** Draft
**Source:** `docs/SRS.md`

## 1. Goal

ให้นักเขียนสร้าง แก้ไข และจัดการหมวดหมู่ของนิยายของตนเอง รวมถึงลบนิยายของตนเองตามเงื่อนไขของระบบ

## 2. Scope

### In Scope

* สร้างนิยาย
* แก้ไขข้อมูลนิยายของตนเอง
* จัดการหมวดหมู่ของนิยายตามความสามารถของระบบ
* ลบนิยายของตนเองตามเงื่อนไขของระบบ

### Out of Scope

* การเผยแพร่และยกเลิกการเผยแพร่นิยาย
* การจัดการตอน
* การจัดการฉากและตัวเลือก
* การกำหนดฉากจบและการตรวจสอบเงื่อนไขก่อนเผยแพร่
* การจัดการหมวดหมู่โดย Admin

## 3. Requirements

### R-NOVEL-01 — สร้างนิยาย

ระบบต้องให้นักเขียนสร้างนิยายได้

**Traceability:** `FR-NOVEL-01`

### R-NOVEL-02 — แก้ไขข้อมูลนิยายของตนเอง

ระบบต้องให้นักเขียนแก้ไขข้อมูลนิยายของตนเองได้

**Traceability:** `FR-NOVEL-02`

### R-NOVEL-03 — จัดการหมวดหมู่ของนิยาย

ระบบต้องให้นักเขียนจัดการหมวดหมู่ของนิยายตามความสามารถของระบบได้

**Traceability:** `FR-NOVEL-03`

### R-NOVEL-06 — ลบนิยายของตนเอง

ระบบต้องให้นักเขียนลบนิยายของตนเองได้ตามเงื่อนไขของระบบ

**Traceability:** `FR-NOVEL-06`

## 4. Acceptance Criteria

* **AC-NOVEL-01** เมื่อนักเขียนสร้างนิยาย ระบบต้องสร้างนิยายเรื่องนั้น
* **AC-NOVEL-02** เมื่อนักเขียนแก้ไขข้อมูลนิยายของตนเอง ระบบต้องบันทึกข้อมูลที่แก้ไขของนิยายเรื่องนั้น
* **AC-NOVEL-03** เมื่อนักเขียนจัดการหมวดหมู่ของนิยาย ระบบต้องบันทึกหมวดหมู่ของนิยายเรื่องนั้นตามความสามารถของระบบ
* **AC-NOVEL-04** เมื่อนักเขียนลบนิยายของตนเอง ระบบต้องลบนิยายเรื่องนั้นเมื่อเป็นไปตามเงื่อนไขของระบบ

## 5. Constraints

* นักเขียนสามารถจัดการเฉพาะนิยายและข้อมูลที่ตนเองมีสิทธิ์จัดการ
* การแก้ไขข้อมูลต้องไม่ทำให้ข้อมูลที่เกี่ยวข้องกับโครงสร้างเนื้อเรื่องเกิดความไม่สอดคล้องกัน
* การเลือกเผยแพร่และยกเลิกการเผยแพร่นิยายอยู่ในขอบเขตของ `018-publish`
* การจัดการตอนอยู่ในขอบเขตของ `014-chapter-management`
* การจัดการหมวดหมู่โดย Admin อยู่ในขอบเขตของ `021-admin-category`
* การจัดการนิยายโดย Admin อยู่ในขอบเขตของ `025-admin-novel-management`
* ชื่อเรื่อง (`title`) ต้องไม่เกิน 100 อักขระ และ Backend ต้องตรวจสอบค่านี้ (`VAL-01`)
* คำโปรย (`captions` / `tagline`) ต้องไม่เกิน 200 อักขระ และ Backend ต้องตรวจสอบค่านี้ (`VAL-02`)
* นิยายหนึ่งเรื่องมีได้ไม่เกิน 3 หมวดหมู่ (`category_ids`) และ Backend ต้องตรวจสอบค่านี้ (`VAL-06`)
* รูปปกนิยายต้องไม่เกิน 10MB และเป็นไฟล์ภาพประเภท JPEG, PNG หรือ WebP เท่านั้น (`VAL-08`, `VAL-10`)
* คำนำนิยาย (`introduction`) เป็นเนื้อหาแบบยาว ระบบต้องไม่จำกัดจำนวนอักขระ (`VAL-11`)
* การตรวจสอบข้อมูลขาเข้าเป็นไปตาม `FR-VALID-01` ซึ่งเป็นข้อกำหนดกลางตาม `docs/SRS.md` §3.1.17 — กฎ `VAL-01` ถึง `VAL-11` เป็นแหล่งอ้างอิงค่ากฎตามเดิม

## 7. Open Questions

* ข้อมูลใดบ้างที่นักเขียนต้องให้ในการสร้างนิยาย และมีข้อมูลใดที่ระบบกำหนดให้บังคับกรอก
  * **ข้อยุติจากการตรวจสอบระบบจริง:** บังคับกรอก `title` (3-100 อักขระ), `description` (10-1000 อักขระ), หมวดหมู่อย่างน้อย 1 หมวดหมู่ ส่วนรูปภาพปก (`image_url` / ไฟล์อัปโหลด) เป็นไปตามเงื่อนไข MinIO
* นิยายที่สร้างขึ้นใหม่เริ่มต้นด้วยสถานะการเผยแพร่ใด และแสดงต่อผู้ใช้งานอย่างไร
  * **ข้อยุติจากการตรวจสอบระบบจริง:** เริ่มต้นด้วยสถานะ `draft` (ยังไม่เผยแพร่) แสดงเฉพาะในแดชบอร์ดของนักเขียนเจ้าของเรื่องเท่านั้น ผู้ใช้ทั่วไปจะไม่เห็น
* "จัดการหมวดหมู่ของนิยายตามความสามารถของระบบ" ครอบคลุมการกระทำใดบ้าง เช่น เพิ่ม ลบ หรือแก้ไขความสัมพันธ์ของหมวดหมู่
  * **ข้อยุติจากการตรวจสอบระบบจริง:** สามารถเลือก ผูก และแก้ไขหมวดหมู่ของนิยายได้
* นิยายหนึ่งเรื่องต้องมีหมวดหมู่อย่างน้อยกี่หมวดหมู่
  * **ข้อยุติจากการตรวจสอบระบบจริง:** กำหนดให้อยู่ระหว่าง 1 ถึง 3 หมวดหมู่ต่อเรื่อง (ตามกฎ VAL-06)
* เงื่อนไขของระบบที่กำหนดไว้สำหรับการลบนิยายคืออะไร และมีผลต่อตอน ฉาก ตัวเลือก และข้อมูลของผู้ใช้งานอย่างไร
  * **ข้อยุติจากการตรวจสอบระบบจริง:** นักเขียนลบได้เฉพาะนิยายของตนเอง การลบจะทำ Cascade ลบ Chapters, Scenes, Choices ที่เกี่ยวข้องตามสถาปัตยกรรม Database
