# Feature Specification: Audit Log

**Feature ID:** `026-audit`
**Status:** Draft
**Source:** `docs/SRS.md`

## 1. Goal

ให้ระบบบันทึกประวัติการดำเนินการที่ระบบกำหนดพร้อมข้อมูลผู้ดำเนินการ และให้ Admin ตรวจสอบประวัติดังกล่าวได้โดยป้องกันไม่ให้ผู้ใช้งานที่ไม่มีสิทธิ์เข้าถึง

## 2. Scope

### In Scope

* บันทึกประวัติการดำเนินการที่ระบบกำหนด
* บันทึกข้อมูลผู้ดำเนินการและรายละเอียดที่จำเป็นของเหตุการณ์
* ตรวจสอบประวัติการดำเนินการโดย Admin
* ป้องกันไม่ให้ผู้ใช้งานที่ไม่มีสิทธิ์เข้าถึงข้อมูล Audit Log

### Out of Scope

* การจัดการหมวดหมู่โดย Admin
* การจัดการบัญชีผู้ใช้งานโดย Admin
* การจัดการนิยายโดย Admin
* การจัดการรายงาน
* การแจ้งเตือน

## 3. Requirements

### R-AUDIT-01 — บันทึกประวัติการดำเนินการ

ระบบต้องบันทึกประวัติการดำเนินการที่ระบบกำหนด

**Traceability:** `FR-AUDIT-01`

### R-AUDIT-02 — บันทึกข้อมูลผู้ดำเนินการ

ระบบต้องบันทึกข้อมูลผู้ดำเนินการและรายละเอียดที่จำเป็นของเหตุการณ์

**Traceability:** `FR-AUDIT-02`

### R-AUDIT-03 — ตรวจสอบประวัติการดำเนินการ

ระบบต้องให้ Admin ตรวจสอบประวัติการดำเนินการได้

**Traceability:** `FR-AUDIT-03`

### R-AUDIT-04 — ป้องกันการเข้าถึงข้อมูล Audit Log

ระบบต้องป้องกันไม่ให้ผู้ใช้งานที่ไม่มีสิทธิ์เข้าถึงข้อมูล Audit Log

**Traceability:** `FR-AUDIT-04`

## 4. Acceptance Criteria

* **AC-AUDIT-01** เมื่อมีการดำเนินการตามที่ระบบกำหนด ระบบต้องบันทึกประวัติของการดำเนินการนั้น
* **AC-AUDIT-02** เมื่อบันทึกประวัติการดำเนินการ ระบบต้องบันทึกข้อมูลผู้ดำเนินการและรายละเอียดที่จำเป็นของเหตุการณ์นั้น
* **AC-AUDIT-03** เมื่อ Admin เปิดดูประวัติการดำเนินการ ระบบต้องแสดงประวัติการดำเนินการให้ Admin ตรวจสอบ
* **AC-AUDIT-04** เมื่อผู้ใช้งานที่ไม่มีสิทธิ์พยายามเข้าถึงข้อมูล Audit Log ระบบต้องไม่อนุญาตให้เข้าถึง

## 5. Constraints

* ประวัติการดำเนินการที่ระบบบันทึกต้องเป็นรายการที่ระบบกำหนด
* การตรวจสอบประวัติการดำเนินการต้องเป็นไปตามสิทธิ์ของ Admin
* ผู้ใช้งานที่ไม่มีสิทธิ์ต้องไม่สามารถเข้าถึงข้อมูล Audit Log
* การจัดการบัญชีผู้ใช้งานโดย Admin อยู่ในขอบเขตของ `022-admin-user-management`
* การจัดการหมวดหมู่โดย Admin อยู่ในขอบเขตของ `021-admin-category`
* การจัดการนิยายโดย Admin อยู่ในขอบเขตของ `025-admin-novel-management`
* การจัดการรายงานอยู่ในขอบเขตของ `023-report`

## 7. Open Questions

* การดำเนินการใดบ้างที่ระบบกำหนดให้บันทึกประวัติการดำเนินการ และมีการดำเนินการใดที่ไม่ต้องบันทึก
  * **ข้อยุติจากการตรวจสอบระบบจริง:** มีการบันทึกการกระทำสำคัญ เช่น การเปลี่ยนแปลงสถานะผู้ใช้งาน, การจัดการบทบาท, การสร้าง/แก้ไข/ลบหมวดหมู่, การสร้าง/แก้ไข/ระงับ/ปลดระงับนิยาย, การจัดการรายงาน/คำขอปลดแบน และการเข้าสู่ระบบ
* รายละเอียดที่จำเป็นของเหตุการณ์ที่ต้องบันทึกมีอะไรบ้าง
  * **ข้อยุติจากการตรวจสอบระบบจริง:** ประกอบด้วย `log_id`, `actor_user_id`, `actor_username`, `actor_role`, `action`, `target_type`, `target_id`, `target_name`, `status`, `ip_address`, `metadata` (JSON snapshot ของข้อมูลเดิมและใหม่) และ `created_at`
* ระบบจะแสดงข้อมูลผู้ดำเนินการในระดับใด และต้องปกปิดข้อมูลบางส่วนหรือไม่
  * **ข้อยุติจากการตรวจสอบระบบจริง:** แสดงชื่อ username, role และ ID ของผู้ดำเนินการต่อ Admin โดยปกปิด password/secret ทั้งหมด
* เมื่อการดำเนินการไม่สำเร็จ ระบบต้องบันทึกประวัติการดำเนินการนั้นหรือไม่ และบันทึกในระดับใด
  * **ข้อยุติจากการตรวจสอบระบบจริง:** ฟิลด์ `status` ใน audit log รองรับทั้ง `SUCCESS` และ `FAILED` โดยบันทึกความผิดพลาดเมื่อระบบเกิดข้อขัดข้องสำคัญ
* ประวัติการดำเนินการมีระยะเวลาการเก็บรักษาหรือไม่
  * **ข้อยุติจากการตรวจสอบระบบจริง:** บันทึกลงตาราง `audit_logs` ในฐานข้อมูล PostgreSQL แบบถาวรโดยไม่มีคิวลบอัตโนมัติ เพื่อรองรับการตรวจสอบย้อนหลัง
* Admin ตรวจสอบประวัติการดำเนินการด้วยเงื่อนไขใดบ้าง และมีการส่งออกข้อมูลหรือไม่
  * **ข้อยุติจากการตรวจสอบระบบจริง:** ค้นหาและกรองได้ตาม `action`, `target_type`, `status`, `actor` (username/id), `target_id`, ช่วงเวลา `date_from`/`date_to` พร้อม pagination ผ่าน `GET /api/admin/audit-logs`
