# Feature Specification: การยื่นคำขอปลดการระงับ

**Feature ID:** `024-unban-appeal`
**Status:** Draft
**Source:** `docs/SRS.md`

## 1. Goal

ให้ผู้รายงานยื่นคำขอปลดการระงับพร้อมเหตุผล และให้ Admin ตรวจสอบและจัดการคำขอดังกล่าวตามกระบวนการของระบบ โดยนักเขียนต้องแก้ไขนิยายตามเหตุผลหรือเงื่อนไขที่ Admin กำหนดก่อนดำเนินการปลดการระงับ

## 2. Scope

### In Scope

* ยื่นคำขอปลดการระงับตามเงื่อนไขของระบบ
* ระบุเหตุผลประกอบคำขอ
* ตรวจสอบและจัดการคำขอปลดการระงับโดย Admin
* แก้ไขนิยายตามเหตุผลหรือเงื่อนไขที่ Admin กำหนดก่อนดำเนินการปลดการระงับ

### Out of Scope

* การส่งรายงาน
* การจัดการรายงานโดย Admin
* การระงับการเผยแพร่นิยาย
* การจัดการสถานะนิยายโดย Admin
* การแก้ไขเนื้อหานิยายของนักเขียน

## 3. Requirements

### R-APPEAL-01 — ยื่นคำขอปลดการระงับ

ระบบต้องให้ผู้รายงานยื่นคำขอปลดการระงับได้ตามเงื่อนไขของระบบ

**Traceability:** `FR-REPORT-07`

### R-APPEAL-02 — ระบุเหตุผลประกอบคำขอ

ระบบต้องให้คำขอปลดการระงับระบุเหตุผลประกอบคำขอ

**Traceability:** `FR-REPORT-08`

### R-APPEAL-03 — ตรวจสอบและจัดการคำขอปลดการระงับ

ระบบต้องให้ Admin ตรวจสอบและจัดการคำขอปลดการระงับได้

**Traceability:** `FR-REPORT-09`

### R-APPEAL-04 — แก้ไขนิยายก่อนดำเนินการปลดการระงับ

นักเขียนต้องแก้ไขนิยายตามเหตุผลหรือเงื่อนไขที่ Admin กำหนดก่อนดำเนินการปลดการระงับตามกระบวนการของระบบ

**Traceability:** `FR-REPORT-10`

## 4. Acceptance Criteria

* **AC-APPEAL-01** เมื่อผู้รายงานยื่นคำขอปลดการระงับ ระบบต้องรับคำขอนั้นเมื่อเป็นไปตามเงื่อนไขของระบบ
* **AC-APPEAL-02** เมื่อยื่นคำขอปลดการระงับ ระบบต้องบันทึกเหตุผลที่ระบุประกอบคำขอนั้น
* **AC-APPEAL-03** เมื่อ Admin เปิดดูคำขอปลดการระงับ ระบบต้องแสดงคำขอที่ส่งเข้ามา และเมื่อ Admin จัดการคำขอ ระบบต้องดำเนินการตามกระบวนการของระบบ
* **AC-APPEAL-04** เมื่อนักเขียนยังไม่ได้แก้ไขนิยายตามเหตุผลหรือเงื่อนไขที่ Admin กำหนด ระบบต้องไม่ดำเนินการปลดการระงับ

## 5. Constraints

* การยื่นคำขอปลดการระงับต้องเป็นไปตามเงื่อนไขของระบบ
* คำขอปลดการระงับต้องระบุเหตุผลประกอบ
* การตรวจสอบและจัดการคำขอปลดการระงับต้องเป็นไปตามสิทธิ์ของ Admin
* นักเขียนต้องแก้ไขนิยายตามเหตุผลหรือเงื่อนไขที่ Admin กำหนดก่อนดำเนินการปลดการระงับ
* การส่งรายงานและการจัดการรายงานอยู่ในขอบเขตของ `023-report`
* การจัดการสถานะของนิยายโดย Admin อยู่ในขอบเขตของ `025-admin-novel-management`
* การแก้ไขเนื้อหานิยายอยู่ในขอบเขตของ `013-writer-novel-management`

## 7. Open Questions

* ผู้รายงานยื่นคำขอปลดการระงับได้เมื่อใด และต้องเป็นเจ้าของนิยายหรือผู้รายงานเดิมเท่านั้นหรือไม่
* หนึ่งนิยายสามารถมีคำขอปลดการระงับที่ยังดำเนินการอยู่กี่คำขอ
* เหตุผลประกอบคำขอมีรูปแบบหรือข้อกำหนดด้านความยาวหรือไม่
* สถานะของคำขอปลดการระงับมีสถานะใดบ้าง และสถานะใดที่อนุญาตให้ Admin ดำเนินการได้
* เหตุผลหรือเงื่อนไขที่ Admin กำหนดเพื่อให้นักเขียนแก้ไขก่อนดำเนินการปลดการระงับ มีรูปแบบและขอบเขตเช่นใด
* ระบบตรวจสอบอย่างไรว่านักเขียนได้แก้ไขนิยายครบตามเงื่อนไขที่ Admin กำหนดแล้ว
* หลังปลดการระงับแล้วสถานะของนิยายเป็นอย่างไร และต้องเผยแพร่ใหม่หรือไม่
* ผู้รายงานและนักเขียนได้รับการแจ้งเตือนผลการจัดการคำขอหรือไม่
